## 1. 왜 노트북을 둘로 나눴는가

처음에는 하나로 시작했다. 가이드북대로 데이터를 읽고 모델을 돌리면 되는 줄 알았다.
그런데 데이터를 뜯어보는 과정에서 **성격이 다른 두 질문**이 나왔다.

| 질문                                | 답하는 방법                    | 노트북 |
| ----------------------------------- | ------------------------------ | ------ |
| 이 설비가 규격을 지킬 능력이 있는가 | 제조 표준 지표 (Cp/Cpk/Pp/Ppk) | 01     |
| 이상이 났을 때 어떻게 잡을 것인가   | 시계열 모델 + 규칙             | 02     |

**앞의 것은 통계고 뒤의 것은 기계학습이다.** 쓰는 도구도, 판단 기준도, 대상 데이터도 다르다.

|           | 01 공정능력                 | 02 TFT                    |
| --------- | --------------------------- | ------------------------- |
| 대상      | **학습 데이터** (정상 구간) | 테스트 데이터 (이상 포함) |
| 시간 척도 | 7개월                       | 하루                      |
| 지표      | Cpk / Ppk / 잔여 개월       | 재현율 / 정밀도 / F1      |
| 결과물    | "언제 정비해야 하는가"      | "지금 이상인가"           |

억지로 합치면 둘 다 흐려진다. 그래서 나눴다.

## 1-2. 왜 이 두 가지였는가 — 실제 진행 순서

**출발점은 가이드북 재현이었다.** N-HiTS를 세 형태로 돌렸는데
어떤 변형도 규칙(F1 0.95)을 이기지 못했다. 그리고 이상한 현상이 관찰됐다.

```
안정화 학습:  예측 MAE 3.723 → 1.038 (3.6배 개선)
             탐지 F1  0.3130 → 0.1469 (절반으로 악화)
```

**더 좋은 모델이 더 나쁜 결과를 냈다.** 이 역설의 원인을 찾는 것이 시작이었다.

### 왜 공정능력 분석인가

원인을 찾으려면 모델이 아니라 **데이터**를 봐야 했다.
가이드북도 조원도 Training_Data를 "정상의 정의"로만 썼다. 그 안을 보지 않았다.

그래서 학습 데이터를 **설비 이력**으로 다시 읽었다.
그리고 그것을 말하려면 제조 표준 언어가 필요했다.
"gap이 내려간다"보다 **"Cpk 6.88인데 Ppk 0.81이다"**가 정확하고 방어 가능하다.

### 왜 TFT인가

공정능력 분석에서 39주기 구조를 알아냈고, 그러자 역설의 원인이 보였다.
**인코더 길이 20은 주기의 절반이다.** 모델이 사이클의 어디인지 모르는 상태로 예측하고 있었다.

이 가설을 검증하려면 **공변량을 받는 모델**이 필요했다.
N-HiTS는 순수 시계열 모델이라 PageNo를 넣을 수 없다. **그래서 TFT다.**

```
01의 목적:  학습 데이터가 정말 정상인지 검증 + 언제 벗어날지 예측
02의 목적:  인코더 길이가 원인인지 검증 + 구조를 반영하면 달라지는지
```

## 2. 어떤 순서로 봐야 하는가

### 반드시 01 → 02 순서로 본다

02는 01의 결론 위에 서 있다. 구체적으로 **02의 핵심 설정 두 개가 01에서 나온다.**

```
01에서 발견:  39포인트 = 1사이클  (3,481회 반복, 예외 0건)
        ↓
02의 설정:    인코더 길이 = 78 (39 × 2)      → val_loss 139 → 8.5
              공변량 = PageNo                 → val_loss 8.5 → 1.2
```

01을 건너뛰고 02만 보면 **"왜 하필 78인가"**에 답할 수 없다.
그리고 그 숫자가 이 프로젝트에서 가장 큰 개선을 만들었다.

### 각 노트북 안에서의 흐름

**01은 좁혀 들어가는 구조다.**

```
데이터 전체 → 변수 선별 → 자리별 구조 → 규격 위치 → 능력 지수 → 추세 → 잔여 수명
```

앞 단계의 결과가 다음 단계의 입력이 된다. 순서대로 봐야 한다.

**02는 실험을 쌓아가는 구조다.**

```
누수 검사 → 조건 A-20 → 조건 A → 조건 B → 조건 C → threshold → 탐지 평가
```

조건을 하나씩 바꿔가며 **무엇이 효과를 냈는지 분리**한다.
중간을 건너뛰면 "공변량이 도움이 됐다"는 결론의 근거가 사라진다.

## 3. 왜 이렇게 만들었는가 — 설계 원칙

### 원칙 1. 수치 표보다 그림

39자리 표를 숫자로 보면 읽히지 않는다. 그래서 **변곡점이 눈에 보이게** 그렸다.

| 그림                             | 무엇이 보이나                         |
| -------------------------------- | ------------------------------------- |
| 고유값 로그 막대                 | 어느 변수가 분산 0인지 (빨간 막대)    |
| 설정 조합 파레토                 | 648가지 중 실제로 11가지뿐이라는 것   |
| gap 분포 + 규격선                | **가운데(목표 0)가 비어 있다**는 것   |
| Cpk vs Ppk 나란히                | 단기와 장기가 3~8배 벌어진다는 것     |
| 시간축 추세 + 화살표             | 1월 −68.4 → 7월 −76.9                 |
| 잔여 수명 외삽                   | 규격선에 닿는 지점에 세로선           |
| 인코더 20 vs 78 색칠             | 20이 주기의 절반밖에 못 본다는 것     |
| val_loss 로그 막대 + 배수 화살표 | 16.4배 / 6.9배                        |
| \|z\| 로그 산점도                | **정상과 이상 사이가 비어 있다**는 것 |

숫자 표는 그림 아래 마크다운에 함께 적었다. 그림으로 보고 숫자로 확인하는 순서다.

### 원칙 2. 각 셀마다 "무엇을 볼 것인가"를 먼저 쓴다

코드 셀 위에는 목적을, 아래에는 해석을 붙였다.

```
[마크다운]  왜 이걸 보는가 + 무엇이 나오면 무슨 뜻인가
[코드]      실행
[마크다운]  실제로 나온 값 + 발견 ①②③...
```

발견에 번호를 붙인 이유는 **나중에 보고서에서 참조**하기 위해서다.

### 원칙 3. 판정 기준을 결과보다 먼저 쓴다

결과를 보고 해석을 갖다 붙이면 원하는 결론이 나온다.
그래서 실험 전에 기준을 박아뒀다.

예를 들어 02의 조건 C 실험에는 이런 기준이 미리 적혀 있다.

```
B의 수렴 후 val_loss 변동폭(1.24~2.19, 폭 0.95)을 잡음으로 본다.
→ ±1 밖만 실제 차이로 인정한다.
```

C가 3.05로 나왔으므로 "확실한 악화"로 판정했다. 기준이 없었다면
"3.05도 나쁘지 않다"고 넘어갔을 것이다.

### 원칙 4. 실패도 남긴다

02에는 **실패한 실험이 그대로 들어 있다.**

| 실패                               | 왜 남겼나                                   |
| ---------------------------------- | ------------------------------------------- |
| 인코더 20 (val_loss 139)           | 왜 78이어야 하는지의 근거                   |
| 조건 C (val_loss 3.05 + 추론 불가) | "변수를 더 넣으면 좋아진다"가 틀렸다는 증거 |
| 1차 threshold (ng3 F1 0.27)        | threshold를 다시 잡아야 한다는 근거         |

**성공만 적으면 왜 그 선택을 했는지 설명할 수 없다.**
특히 1차 threshold 실패는 이 프로젝트에서 가장 중요한 방법론적 발견으로 이어졌다.

### 원칙 5. 추정과 측정을 구분해서 쓴다

노트북 곳곳에 `(추정)`이 붙어 있다.

```
측정:  세 모드 전부 월 0.22~0.25% 비율로 감소한다
추정:  레이저 소스 또는 광학계의 출력 감쇠로 보인다
```

앞은 데이터에서 나왔고 뒤는 물리적 해석이다.
설비 사양서가 없으므로 뒤는 확정할 수 없다. **섞어 쓰면 발표에서 무너진다.**

## 4. 두 노트북이 만나는 지점

### 4-1. 39주기 — 01의 발견이 02의 설정이 된다

01 §5에서 확인한다.

```
(PageNo, SetPower) 조합 = 39개 = PageNo 개수
pos == PageNo 전부 True (147개 조각 어디에서도 어긋나지 않음)
```

02 §3에서 그 구조를 인코더 길이로 옮긴다.

```
인코더 20 → 주기의 절반. 지금이 사이클의 몇 번째인지 알 수 없다
인코더 78 → 두 사이클. 반복 구조가 드러난다
```

**결과: val_loss 139.10 → 8.48 (16.4배)**

다른 것은 아무것도 바꾸지 않았다. 이것은 탐색으로 찾은 값이 아니라
**데이터 구조에서 도출한 값**이다. 가이드북과 조원은 20을 썼다.

### 4-2. 변수 종속 — 01의 관찰이 02의 공변량 설계가 된다

01 §3에서 확인한다.

```
648가지 조합 중 실제로는 11가지
PageNo → SetPower, Speed, Length, GateOnTime  (전부 완전 결정)
```

02 §2 누수 검사에서 다시 확인하고, §5에서 실험으로 검증한다.

```
공변량 PageNo만        val_loss 1.24
공변량 3개 (중복)      val_loss 3.05  ← 악화
```

**"변수를 더 넣으면 좋아진다"가 틀렸다는 것을 실험으로 보였다.**

### 4-3. 열화 — 01의 추세가 02의 threshold 문제를 설명한다

01 §10에서 7개월 열화를 확인한다 (순위상관 −0.94 이하).

02 §8에서 모델 A의 학습 전체 잔차 평균이 **+9.70으로 밀린 것**을 발견하는데,
이것은 **공변량이 없는 모델이 장기 하강을 따라가지 못한 것**으로 해석된다(추정).

01을 안 봤다면 이 현상을 설명할 수 없었을 것이다.

## 5. 두 축은 무엇을 담당하고 어디서 합쳐지는가

### 5-1. 서로 다른 질문에 답한다

|           | 01 공정능력                | 02 TFT             |
| --------- | -------------------------- | ------------------ |
| 질문      | **언제 규격을 벗어나는가** | **지금 이상인가**  |
| 대상      | 학습 데이터 7개월          | 테스트 데이터 하루 |
| 시간 척도 | 월                         | 초·분              |
| 결과물    | 잔여 1.8~2.4개월           | 4파일 오류 0건     |

**하나만 보면 반쪽이다.**

- 02만 보면 "이상을 잘 잡는다"로 끝난다.
  그런데 이 데이터셋의 이름은 **예지보전**이다. 탐지는 예지가 아니다.
- 01만 보면 진단은 되지만 **탐지 수단이 없다.**

### 5-2. 그런데 별개가 아니다 — 01이 02를 만들었다

```
01의 발견                          02의 설정                결과
────────────────────────────────────────────────────────────────
39포인트 = 1사이클          →     인코더 78 (39×2)    →   139 → 8.5
자리당 설정이 정확히 하나    →     공변량 PageNo       →   8.5 → 1.2
설정 5변수가 PageNo에 종속   →     공변량 3개 기각      →   3.0 (악화 확인)
```

**02의 성능은 01 덕분에 나왔다.** 튜닝으로 찾은 값이 아니다.

반대 방향도 있다. 02 §8에서 모델 A의 잔차 평균이 +9.70으로 밀린 것을 발견했는데,
**01의 7개월 열화를 알고 있었기에** "공변량 없는 모델이 장기 하강을 못 따라간 것"으로
해석할 수 있었다. 01을 안 봤다면 설명할 수 없는 현상이다.

### 5-3. 등급 체계에서 합쳐진다

두 축의 결과를 하나의 판정 체계로 묶는다.

| 등급         | 판정                     | 출처     | 시간 척도 | 8/3 발동 |
| ------------ | ------------------------ | -------- | --------- | -------- |
| **즉시정지** | RealPower = 0            | 규칙     | 즉시      | 16:35    |
| **경보**     | 설정 미지값 OR 규격 이탈 | 규칙 A·B | 분        | 15:24    |
| **주의**     | TFT \|z\| > 5.71         | **02**   | 시간      | —        |
| **예지**     | 열화 추세 외삽 도달      | **01**   | 월        | 7월 말   |

**네 등급 중 둘이 02에서, 둘이 01에서 나온다.**

### 5-4. 왜 대체가 아니라 등급인가

세 방법이 **서로 다른 것을 본다.**

|          | 보는 것             | 강한 곳              | 약한 곳                  |
| -------- | ------------------- | -------------------- | ------------------------ |
| 규칙 A   | SetPower 설정       | 설정 오입력          | 설정 정상이면 무력       |
| 규칙 B   | 규격 ±80            | 큰 이탈              | 규격 내 이상             |
| TFT B    | RealPower 예측 잔차 | 문맥상 이상          | **이상이 지속되면 적응** |
| 공정능력 | 장기 산포·중심 이동 | 서서히 진행되는 열화 | 급성 사건                |

02 §11이 그 증거다. **규칙 A는 잡고 TFT는 놓친 2건**이 있다.
SetPower가 35로 오설정된 상태였는데, 인코더 78(두 사이클)이 **이미 그 이상 상태**여서
모델이 681을 정상으로 학습했다. 잔차가 −0.08밖에 나오지 않는다.

> **이상이 인코더 길이보다 오래 지속되면 모델은 적응한다.**
> 규칙은 문맥을 보지 않으므로 지속 여부와 무관하게 잡는다.
> 둘을 합쳐야 서로의 약점이 메워진다.

놓침이 치명적이지만, 경보가 하루 수십 번 뜨면 현장이 무시하기 시작한다(경보 피로).
**확실한 이상은 경보로, 의심스러운 것은 주의로 나누면** 놓치지 않으면서 대응 우선순위가 생긴다.

## 6. 각 노트북에서 가장 중요한 셀

시간이 없으면 이것만 봐도 된다.

### 01\_공정능력분석

| 셀               | 내용                            | 왜 중요한가                                     |
| ---------------- | ------------------------------- | ----------------------------------------------- |
| §6 gap 분포      | 규격 안 어디에 있는가           | **목표값 근처가 비어 있다** — 양 벽에 붙어 있음 |
| §7 Cpk vs Ppk    | 단기 vs 장기                    | **2.2~6.9 vs 0.81~1.22** — 진단의 핵심          |
| §10 세 모드 추세 | 월 0.22~0.25% 감소              | 설비 공통 요인이라는 근거                       |
| §7-1 정규성      | Shapiro p ≤ 1e-30, 고유값 12~37 | Cpk 해석의 방어                                 |
| §7-2 비모수      | 저출력 일치, 고출력 갈림        | 전제가 결론을 흔드는지                          |
| §9-1 관리도      | 이탈 98.6%, σ_within 0.261      | **정밀하지만 관리 불능**                        |
| §9-2 WE 규칙     | 99.5% 위반, 최초 1/18           | **표준 도구로도 열흘 만에 보였다**              |

## 8. 이 분석을 어떻게 읽어야 하는가

### 숫자보다 순서를 봐라

이 노트북의 핵심은 성능 숫자가 아니다. **무엇을 보고 무엇을 결정했는지**의 사슬이다.

```
39주기 확인  →  인코더 78  →  16.4배 개선
자리당 설정 고정 확인  →  공변량 PageNo  →  6.9배 개선
변수 종속 확인  →  공변량 3개 기각  →  악화 확인
검증 표본 부족 확인  →  threshold 재설정  →  F1 0.27 → 1.00
```

**데이터를 읽은 것이 설정을 정했고, 설정이 결과를 만들었다.**
튜닝으로 찾은 것이 아니다.

### 한계를 먼저 읽어라

`분석보고서.md` §9에 한계가 정리돼 있다. 세 가지는 반드시 알고 봐야 한다.

1. **이상 사건이 2개뿐이다.** 2개로 만든 판정을 그 2개로 평가하는 구조다.
   재현율 1.0이라는 숫자를 일반화할 근거가 없다.
2. **규칙 A는 테스트셋을 먼저 보고 만들었다.**
   논리적으로는 학습 데이터만으로 도출 가능하지만, 실제 순서는 반대였다.
3. **threshold를 1차 평가 후에 바꿨다.**
   바꾼 이유(표본 1,817행의 불안정성)는 결과와 무관하지만, 시점은 기록해야 한다.

**반대로 해소된 한계도 있다.**

| 항목                      | 해소 방법                                          |
| ------------------------- | -------------------------------------------------- |
| 백분위수 99.9는 임의 선택 | 99.0~100.0 민감도 분석 → 99.9 이상 전 구간 동일    |
| σ_within 계산 방식        | R̄/d₂ 0.261 vs 군별 표준편차 평균 0.373 → 결론 동일 |
| 자리별 σ 차이 원인        | 해상도 가설 기각(상관 −0.407). 폭 6%로 무시 가능   |

이것을 감추면 질의응답에서 무너지고, 밝히면 오히려 신뢰가 생긴다.

### 가이드북과 비교하며 읽어라

가이드북은 잘못된 문서가 아니다. **일반적인 접근을 보여주는 교재**다.
다만 이 데이터의 특수한 구조를 반영하지 않았을 뿐이다.
